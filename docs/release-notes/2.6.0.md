Changes since [v2.5.0](https://github.com/Matt17BR/openwrangler/releases/tag/v2.5.0) improve row consistency and add file-plan reuse and DuckDB table browsing.

- Keep notebook and Custom Code rows stable across pages and column windows in Polars and DuckDB.
- Inspect applied Custom steps without producing different rows on each request.
- Reuse a cleaning plan on another compatible Pandas, Polars or DuckDB file.
- Browse local DuckDB tables with filters and column profiles.
- Keep keyboard focus when moving through import options.

<details>
<summary>Read more: migration, improvements and remaining limits</summary>

DuckDB notebook opening now asks for the relation's originating connection. Expose it as a notebook variable, or select the default connection when it is the owner. Keep it open while viewing; another connection to the same database does not qualify.

Regenerate exported scripts to receive the fixes. Generated DuckDB plans containing Custom Code now require `result = clean_data(frame, connection=con)`, using the connection that created `frame`. Each Custom result must derive from its supplied `df`; results from another connection are refused.

Captures evaluate complete results before paging, adding execution time and memory use; DuckDB file Custom results also use temporary disk storage. Preview and inspection can retain multiple results. Page limits do not bound capture, and later native queries over generated DuckDB results can incur substantial overhead. Custom replay, including the first inspection, may produce fresh values. See the [capture and ownership limits](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md#sessions-and-generated-code).

Explode List expands Polars List columns; Extract Struct Fields supports Polars and DuckDB file sessions. File-plan reuse excludes Custom Code, unfinished drafts and targets with existing saved work.

Code Preview labels the inspected step above the code. Operation dialogs can hide the catalog without clearing settings. Profiles and filters no longer cover keyboard-selected cells in narrow panes, and failed viewing queries preserve newer staged sorts.

[Jupyter's blank Variables pane](https://github.com/Matt17BR/openwrangler/issues/1498) remains unresolved, observed with Jupyter 2025.9.1 in Linux VS Code 1.137.0. Specific notebook toolbar and inline routes passed installed checks independently; recovery after that same blank-pane failure remains unverified.

DuckDB file/database support remains experimental; database views are unavailable. Close all database viewers before writing to the database. DuckDB table and notebook sessions and PySpark notebooks remain viewing-only. R terminal/document support remains Preview, and Cursor remains experimental. See the [versioned capability guide](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md).
