Changes since [v2.5.0](https://github.com/Matt17BR/openwrangler/releases/tag/v2.5.0) expand native R file and nested-column workflows, improve profiles, and keep notebook and cleaning results consistent across pages.

- Open CSV, TSV, flat Parquet and JSONL/NDJSON files, or an Excel worksheet, directly with R on Linux, macOS and Windows (Preview).
- View timezone-free and nanosecond Parquet timestamps exactly in R, with supported cleaning in base R and dplyr.
- Reuse a cleaning plan on another compatible Pandas, Polars, DuckDB or R file.
- See complete R numeric histograms, exact counts within documented bounds, and clearer column profiles.
- Browse local DuckDB tables and keep Polars LazyFrame and DuckDB notebook rows stable across pages.

<summary>Read more: migration, improvements and remaining limits</summary>

Local R files support cleaning, generated R and saved plans without Python. Select R in the engine picker or `openWrangler.defaultBackend`. Auto also tries R when no compatible Python engine is available. An explicit engine choice or a file-read error does not switch to R. Engine and import-option changes open a separate session and preserve the original work.

Local R files with missing or incompatible packages offer **Install required packages**. Review the selected Rscript environment and target package library before confirming installation. Open Wrangler validates the result and retries the same file. Live R notebooks and terminals retain manual installation.

R CSV/TSV imports honor the supported encodings, ASCII delimiter and quote choices, headerless input and CR records, with matching generated code. Quoted text retains embedded line endings. Parquet accepts supported legacy integer annotations, including DuckDB output. Refused fields identify the incompatible representation and suggest a compatible engine or explicit conversion.

R Parquet import and export now require `arrow`; imports and zero-column exports also need `nanoparquet`. Exact timestamp columns require `clock`. Excel needs `readxl`, and large integer input needs `bit64`. R reads the complete file into memory; editing can retain additional copies. See the [reader and export limits](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/architecture.md#native-r).

R List columns contain atomic vectors of one native type; Struct columns contain flat records with matching scalar fields. Extract Struct Fields appends fields, and Explode List expands a typed list while repeating other columns. Empty or missing lists retain one row. Recursive containers and mixed types are unsupported. Nested viewing supports missing-value filters, but not sorting, value pickers or distributions. R data exports require scalar columns: extract and drop record columns, or explode typed lists first.

Select base R, dplyr, data.table or collapse in the engine picker or `openWrangler.defaultRLibrary`. The toolbar shows the confirmed choice independently of the dataframe class. Choosing another library opens an editing copy and replays applied steps; the original keeps its draft and redo history. Applied Custom Code runs again only after confirmation. Selected packages must be installed in the owning R environment. Imports, profiles and exports keep their shared native implementations. See the [library requirements](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md#r-cleaning-libraries).

All four R library choices open timezone-free and nanosecond Parquet timestamps exactly. Timezone-free values keep their local meaning; UTC-adjusted values display in UTC. Base R and dplyr support the documented row and column operations with matching generated R. With data.table or collapse selected, these frames support viewing and export; choose base R or dplyr to create an editing copy. Some operations on these columns remain unavailable. See the [timestamp limits](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md#frames-cleaning-and-export-limits).

Ordinary R `POSIXct` timestamps now round to microseconds in the grid, copied cells and profiles. Convert Type to text and its generated R use the same formatting, fixing a one-microsecond display error. Source values retain their original precision. Explicit Format Datetime and existing One Hot column names keep their native formatting.

R Parquet export refuses durations that cannot convert exactly from their R units to nanoseconds, including sub-nanosecond values, NaN, infinity and overflow, instead of changing them silently.

R Custom Code can use installed `dplyr`, `data.table` and `collapse` packages and return a different supported dataframe class. Base `data.frame`, tibble and `data.table` results retain their class through Preview, history and generated execution. Final grouped or indexed objects still require conversion.

R profiles honor the opening preference and avoid offscreen header work. Numeric histograms count every finite value; large numeric columns display exact distinct counts through 10,000 distinct values. Columns containing only infinities also open their profiles without a protocol error. Categorical distributions remain exact within [documented bounds](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/architecture.md#viewing-and-profiling), with clear sample-population labels beyond them. Higher-cardinality numeric distinct counts and large numeric medians remain unavailable.

R text profiles and Lowercase/Uppercase avoid repeated scalar conversion. Pandas profiles of nonmissing object-string columns and nullable missing-value filters also avoid unnecessary per-value work, while retaining their type and missing-value rules.

R terminal commands honor `r.bracketedPaste` for radian. Normal dataframe-discovery updates no longer cause an R terminal session cleanup error. Sorting and reducing CSV-derived R frames accept native row-name changes. R startup paths and generated code preserve Unicode text, including supplementary characters alongside escaped controls.

File-plan reuse accepts matching original column names and types in a different order. It excludes Custom Code, unfinished drafts and targets with existing saved work. Explode List also supports Polars List columns. Extract Struct Fields supports Polars editing sessions and DuckDB file sessions as well as native R. Convert Type to Datetime accepts day-first, month-first and ISO text dates through an optional input layout.

DuckDB notebook opening now asks for the relation's originating connection. Expose it as a notebook variable, or select the default connection when it is the owner. Keep it open while viewing; another connection to the same database does not qualify.

Regenerate exported scripts to receive the fixes. Generated DuckDB plans containing Custom Code now require `result = clean_data(frame, connection=con)`, using the connection that created `frame`. Each Custom result must derive from its supplied `df`; results from another connection are refused.

Polars and DuckDB captures evaluate complete results before paging, adding execution time and memory use; DuckDB file Custom results also use temporary disk storage. Preview and inspection can retain multiple results, and later queries over generated DuckDB results can add substantial overhead. Applied Custom inspection reuses captured rows; replay, including the first inspection, may produce fresh values. Page limits do not bound capture. See the [capture and ownership limits](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md#sessions-and-generated-code).

Data sources groups file opening and discovered Python/R dataframes; Operations holds the cleaning catalog. Column profiles and cleaning controls remain readable in narrow panes, and Code Preview labels the inspected step. Import questions preserve keyboard focus, and package setup keeps its status and install action visible beside long errors. The engine picker identifies Python and R choices consistently and shows whether a choice switches the current tab, opens a new tab or creates an editing copy.

Applying a cleaning step preserves new grid selections and keyboard focus instead of clearing them with a delayed view restoration. Opening Code Preview also keeps the current selection.

[Jupyter's blank Variables pane](https://github.com/Matt17BR/openwrangler/issues/1498) remains unresolved, observed with Jupyter 2025.9.1 in Linux VS Code 1.137.0. Specific notebook toolbar and inline routes passed installed checks independently; recovery after that same blank-pane failure remains unverified.

R notebook support for ordinary supported frames remains stable in desktop VS Code on Linux, macOS and Windows. R local files remain Preview on those platforms. R terminal support remains Preview on Linux; managed `.R`, `.Rmd` and `.qmd` documents remain Preview on Linux and macOS. Windows file support does not include managed R scripts. Cursor remains experimental.

DuckDB file/database support remains experimental; database views are unavailable. Close all database viewers before writing to the database. DuckDB table and notebook sessions and PySpark notebooks remain viewing-only. See the [versioned capability guide](https://github.com/Matt17BR/openwrangler/blob/v2.6.0/docs/feature-parity.md).
