Since [v2.2.0](https://github.com/Matt17BR/openwrangler/releases/tag/v2.2.0), this release fixes malformed CSV exports in Polars and native R.

- Polars refuses custom delimiters or quotes that could corrupt numeric, Boolean or date/time fields.
- Native R quotes dates, timestamps and 64-bit integers so custom CSV delimiters keep fields separate.
- Native R carries rounded timestamps into valid dates and times, including across daylight-saving transitions.

<details>
<summary>Read more: CSV limits and generated-code improvements</summary>

Comma, tab, semicolon and pipe with ordinary double quotes remain available. Some custom settings that previously appeared to succeed now produce an explicit refusal. Polars applies this restriction by column type even for empty, all-null or otherwise non-conflicting values. Native R refuses conflicting numeric/logical delimiters when those columns contain non-missing values.

R CSV timestamps still round fractional seconds and omit timezone information; this release does not provide exact timestamp preservation. Native R remains Preview. See the [versioned capability limits](https://github.com/Matt17BR/openwrangler/blob/v2.3.0/docs/feature-parity.md) before transferring timestamps between tools.

Generated DuckDB code avoids repeated scans when checking output names. Existing exported scripts and CSV files do not change after upgrading; regenerate affected scripts or export the data again.
