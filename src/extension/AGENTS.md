# Extension-host instructions

This file applies to `src/extension/**`. Read the root policy first. Shared messages and operation contracts require `src/shared/AGENTS.md`; renderer behavior requires `src/webviews/AGENTS.md`; runtime-specific changes require the corresponding Python or R owner.

## Owned invariants

<!-- OW-RULE:I06 -->
6. Disposing a panel closes its runtime session. A runtime crash rejects pending work and offers replay/recovery.

<!-- OW-RULE:I12 -->
12. Standalone runtime startup is single-flight per Python-selection scope. A workspace folder, exact external resource, and the default resource own distinct process/start/stop, pending, provisional, and confirmed-session state; session requests and cancellations route only through their exact owner. A requested session ID may route only cleanup while provisional, becomes confirmed only through its exact still-pending open response, and any late or ambiguous promotion restarts only that scope. Restart must invalidate the pending start, and closing the final session in a scope must stop its Python process; packaged seed/verify acceptance guards these lifecycle rules.

<!-- OW-RULE:I14 -->
14. Saved notebook output is a bounded static inline capture, not runtime or session state. A workbench action may open only the exact current live variable described by invariant 39; captured rows never become a transformation, export, or fallback source.

<!-- OW-RULE:I18 -->
18. View-query freshness is determined by an opaque logical-view context plus each request's `viewRequestId`, never by filter equality or session revision alone. Mutations and exports remain exclusive; one read-only foreground query may overtake a leased immutable profiling view, profiles use bounded background capacity, and closing cancels queued profiles then waits for active leases. Partial summaries, statistics, values, errors, and pages may update UI or retained panel state only when their request still belongs to the confirmed active view. A current renderer-owned summary or dataset-statistics request may recover one lost runtime because it is idempotent, but cancellation or view supersession suppresses reissue, concurrent foreground/background recovery must share one replacement, and mutation retry rules never change.

<!-- OW-RULE:I19 -->
19. Cancellation is authoritative only when the original runtime request returns its own correlated response. A cancellation acknowledgement may remove queued work, but it must never synthesize completion for already-running work or hide a mutation that may have committed.

<!-- OW-RULE:I22 -->
22. `closeSession` is terminal cleanup: its revision is advisory so a caller holding the last confirmed revision can still dispose a runtime that may have committed an ambiguous response. Unknown sessions remain errors, and cleanup still runs at most once.

<!-- OW-RULE:I24 -->
24. Live-kernel opens carry a host-generated `requestedSessionId`. A failed, cancelled, timed-out, malformed, or mis-correlated open must issue a fresh bounded close for that known candidate ID so lost kernel output cannot orphan an unaddressable runtime session.

<!-- OW-RULE:I26 -->
26. Persisted cleaning state is keyed by both source identity and confirmed backend. Recovery replays with that backend pinned; an automatic fallback must never reinterpret a saved plan through another engine.

<!-- OW-RULE:I27 -->
27. Persisted cleaning and viewing sections recover independently. A missing, malformed, or stale view falls back to an empty view on the cleaned runtime without dropping valid steps or a draft; only cleaning replay failure may reopen the immutable original. Debounced presentation state must flush before a webview can disappear.

<!-- OW-RULE:I28 -->
28. Applied-step inspection is bounded, read-only, and ephemeral. It may replay only the selected prefix, never mutate revisions or caches, and must clear across panel switches, recreated webviews, recovery, mutation, disposal, Original Data, and Escape while restoring the exact confirmed view. Diff truncation accounts for rows on either side of the returned block.

<!-- OW-RULE:I34 -->
34. The public dependency-install command accepts no confirmation state and always shows a modal naming the exact requirements and interpreter; only its literal affirmative action may run pip. The `OPEN_WRANGLER_EXTENSION_TESTS=1` activation API exposes only a deterministic decline. There is no modal-free affirmative path or sticky production override. `openWrangler.pythonPath` changes and later successful probes invalidate stale install targets, while a decline preserves the current retryable diagnostic.

<!-- OW-RULE:I36 -->
36. After trust and active-code prerequisites pass, the public **Export Generated Script** command accepts no destination argument and always uses VS Code's Save dialog. Python sessions default to `.clean.py`; R sessions default to `.clean.R`. Only the environment-gated test API may supply a deterministic destination, and it must call the same source guard and writer. The coordinator pins the immutable open-request source instead of trusting runtime-returned source metadata. Script exports accept only the current local host or matching VS Code remote authority, protect every retained source URI/path through normalized, canonical, and usable filesystem-identity checks, reserve an exclusive sibling temp, flush and close it, revalidate that temp's type/identity plus the source, destination, parent mapping, and remote authority immediately before one atomic rename, and clean only that still-identified temp on failure. Never truncate, unlink, follow, or replace the active source or a destination symlink.

<!-- OW-RULE:I38 -->
38. Every live notebook launch owns the exact open `NotebookDocument` captured at command or renderer-message receipt; renderer actions additionally require the exact visible sender `NotebookEditor`. Never recover origin from `activeNotebookEditor` after an await, a URI match, or another split. Retain document identity through coordinator state, Jupyter activation, kernel lookup, bootstrap, dispatch, response publication, recovery, and generated-code insertion. The released Jupyter Variables webview supplies only `fileName`, either as a real `vscode.Uri` or its exact, bounded, canonical VS Code JSON envelope; aliases, strings, malformed caches, and ambiguous documents fail closed. Each dispatched session ID stays mapped to its exact kernel so a malformed, cancelled, timed-out, stale, or mis-correlated open can make one bounded direct cleanup attempt even after lifecycle invalidation. Terminal close may use that mapped kernel but must never reacquire by URI against a replacement document. Generated-code insertion must repeat its exact-object/version/uniqueness preflight immediately before dispatch and report success only after that same document contains the uniquely marked cell. Because the stable VS Code notebook-edit API is URI-addressed, an accepted edit that cannot be proven against the original object is indeterminate and must never be retried, rolled back, or reported as successful; a stale pre-dispatch origin fails without editing a replacement.

<!-- OW-RULE:I39 -->
39. Saved MIME-v2 output remains one canonical, bounded, portable inline capture. Its single **Open in Open Wrangler** action is present only when the validated payload carries one unambiguous `variableName` link, and it always opens the complete current live variable through the exact originating `NotebookDocument`, visible sender `NotebookEditor`, and kernel required by invariant 38. Captured rows never open as a workbench session or silently replace live data. Without a validated live link the renderer shows a concise instruction to run the cell again and sends no open action; the host independently rejects forged or unlinked actions with the same recovery direction. A missing variable or kernel reports that the user must select or start the Python kernel, run the defining cell, and retry. The static inline renderer pages only the captured rows at 10, 20, 50, or 100 rows per page and renders every captured column. Producer and consumer caps must stay identical at 10,000 rows, 2,048 columns, 100,000 cells, 16 MiB, 64 graph levels, and 1,000,000 graph nodes plus their field-text limits; capture performs no eager profiling, and lazy Polars collects only one bounded terminal page. Automatic formatter preparation may run proactively only for a trusted, exact Jupyter notebook and only when `openWrangler.notebookPreviewProvider` resolves to Open Wrangler. When Microsoft Data Wrangler is installed and the preference is `ask`, the user chooses the provider before Open Wrangler registers formatters; changing away from Open Wrangler applies to newly started or restarted kernels. The notebook-toolbar picker discovers a bounded, type-validated variable list through the exact notebook's selected kernel, revalidates exact document provenance around every await, and never guesses or evaluates a name entered as free text.

<!-- OW-RULE:I42 -->
42. Dependency probes are single-flight only for the exact canonical package-root identity, normalized fully qualified executable, Python version, and ordered dependency descriptors. Scope invalidation, package mutation, and shutdown detach the exact in-flight and completed owners; every joined consumer of a detached probe fails stale, and a late success or rejection cannot delete or publish over a same-key replacement. Successful completed results use an independent 128-entry LRU whose hits refresh recency; LRU eviction may cause only a harmless repeat probe. Probe failures are never cached, missing-requirement order remains stable, and no probe subprocess is cancelled or awaited during bridge shutdown.

<!-- OW-RULE:I43 -->
43. Import options are exact and format-specific. Excel selectors are mutually exclusive: interactive prompts produce one nonblank `sheetName` or safe non-negative zero-based `sheetIndex`, while a selector-free default means index 0. Delimited options accept no Excel fields, and delimiter/quote values are exactly one Unicode scalar value; lone UTF-16 surrogates are invalid. There are no legacy `sheet` or mixed-format aliases. Automatic selection excludes Polars for a multibyte UTF-8 delimiter and excludes Polars/DuckDB for a multibyte quote; an incompatible pinned backend fails before interpreter resolution, dependency probing, or runtime startup. Changing options for a live file is a host-owned transaction under the same immutable source and public session ID: synchronously flush pending view state, interlock operation UI and runtime/view-state messages, quiesce accepted work, open one host-identified candidate, replay the confirmed plan/draft/view, publish once, and retire the prior runtime without restart-on-timeout. A correlated replacement is authoritative immediately: its source, revision, and snapshot are adopted before asynchronous workspace-state persistence, while a superseding generation suppresses only stale UI publication. The confirmed publication includes regenerated engine-native code plus any draft diff, warnings, and input schema under the new public revision; stale presentation messages are ignored. Every error, cancellation, stale/malformed response, replay failure, or close race leaves the confirmed snapshot intact and cleans the addressable candidate exactly once. Candidate and retired cleanup retain delegate ownership until settlement, and neither option changes nor any first/fallback terminal cleanup may start a missing runtime or write the source. Every correlated file `sessionOpened` may update the bounded `openWrangler.confirmedFileConfigurations.v2` registry. Its strict entries are keyed by canonical file URI and keep the resolved backend separate from the logical `auto` or explicit backend preference; CSV/TSV/Excel require exact import options, while Parquet/JSONL require that field to be absent. There is no compatibility alias. VS Code permits one Open Wrangler custom editor per URI, and recreation must rehydrate and pin that last confirmed source/backend before the unchanged cleaning/view persistence lookup without converting `auto` into an explicit pin for later import reconfiguration.

<!-- OW-RULE:I45 -->
45. Optional Python-extension environment selection is resource-scoped and event-driven without a hard extension dependency. Activation is single-flight, subscribes to the stable selection event before use, and becomes terminal on disposal. Workspace-folder, exact-file, same-folder sibling, and unscoped events invalidate only current affected scopes; an explicit `openWrangler.pythonPath` ignores those events. Every awaited resolution/probe checks its per-scope epoch. Bare commands resolve only through fully qualified PATH entries and can never be workspace-shadowed; a wrapper is replaced by the absolute `abspath(sys.executable)` it reports, while the executable is never realpathed away from a virtual environment. Windows system discovery uses only the no-install `py -0p` listing and then starts a direct supported `.exe`; dependency probes, pip, and runtimes reject every non-fully-qualified executable. Environment and dependency probes use isolated Python with a controlled environment, return the supported version plus a canonical absolute `realpath(sys.prefix)` and usable string-safe filesystem identity with a 64-bit device and up-to-128-bit inode, and reject an all-zero identity. Live runtimes inherit only owned Python controls and the bundled runtime path, never a host `PYTHONHOME`, `PYTHONPATH`, user site, virtual-environment marker, or launcher override. A confirmed pip mutation invalidates every current selection and process sharing that exact package-root identity, even through executable, symlink, junction, or `/proc` aliases or after its initiating target became stale, while preserving a newer genuinely different package environment. Dependency results are additionally partitioned by normalized executable and exact Python version so distinct interpreters under one shared prefix cannot reuse one another's probe.

<!-- OW-RULE:I46 -->
46. Standalone Python scope retention is one aggregate bundle keyed by selection scope and is bounded to 128 inactive bundles by a monotonic LRU that never reorders runtime slots. Exact-object leases plus local and global pending, provisional, confirmed-session, cancellation, process/start/stop, stopping-child, and actionable missing-dependency ownership prevent eviction; live or leased scopes may temporarily exceed the cap and must trim immediately when ownership releases. Exact synchronous eviction revalidates the slot identity, removes only its matching selection/epoch/recency state, and scrubs its diagnostics and stale process-selection references. Completed dependency probes are bounded independently by invariant 42 and are never retained or evicted merely because a resource scope exists or disappears. A rejected stop remains owned until that exact child later exits. Stale continuations and lease releases must never mutate a same-key replacement, and an orphan unresolved selection fails closed.

<!-- OW-RULE:I47 -->
47. Dependency mutation runs only through the bundled stdlib-only `dependency_guard.py` under the exact fully qualified interpreter confirmed by the isolated environment probe. The guard owns one package-root-local OS lock, durably creates one exclusive UUID marker before publishing READY, accepts package writes only after the parent returns an exact-token GO frame, and retains the lock while it invokes `python -I -m pip install --no-input --no-user` in-process. The controlled environment disables pip configuration, denies inherited `PIP_*` controls except the explicit index/proxy/certificate/cache/network allowlist, and uses one private mode-0700 empty working directory through exact close. Before GO, a package-root-identity mutation barrier invalidates dependency/selection state, quiesces active, pending-start, and already-stopping runtimes, then rechecks lifecycle, Workspace Trust, current selection object and epoch, normalized executable, executable file identity, exact Python version, canonical package-root identity, requirements, and barrier ownership. Host loss before GO cannot start pip; host or OS interruption after GO leaves the marker while the OS lock proves whether that exact writer is still live. Status must run before cached probes or runtime startup. Dirty, busy, malformed, unreadable, identity-changed, or timed-out state fails closed with `dependency_environment_uncertain`. Only a separate exact-token validation that acquires the same OS lock, freshly imports and version-checks every recorded dependency, and observes the same executable/root identity may remove the marker. The trust-gated zero-argument revalidation command must rediscover the exact retained target, recheck status before and after its modal, re-quiesce matching runtimes, and never expose a token, affirmative test seam, Clear, Ignore, expiry, record-only cleanup, or user-attestation bypass. Install and recovery are locally mutually exclusive and stale completion may clear only its own UUID. Every one-shot status or validation helper is owned until exact close; shutdown idempotently unreferences its child and pipes without waiting or signalling it, and actionless notification lifetime may never retain a single-flight operation or mutation barrier. Shutdown may wait briefly and unref an authorized guard once, but it must never signal or kill it; pending UI and late completion publish nothing after disposal. On Windows, journal and leaf creation uses a protected explicit DACL owned by the current token user and grants full control only to that user, LocalSystem, and Builtin Administrators. Exact owner, protection, and ACE validation is handle-bound; the exact no-delete journal handle stays pinned for the complete OS-lock critical section. A pre-existing or changed nonconforming v1 journal fails closed and is never repaired, deleted, or silently replaced.
