# Python runtime instructions

This file applies to `python/**`. Read the root policy first. Protocol and operation changes also require `src/shared/AGENTS.md`; host lifecycle or dependency-selection changes require `src/extension/AGENTS.md`; executable gates and public claims require their scripts and docs owners.

## Owned invariants

<!-- OW-RULE:I01 -->
1. Pandas, Polars, DuckDB, and PySpark paths remain engine-native. Polars code must never call `to_pandas()`; DuckDB code must never convert through Pandas, Polars, or Arrow. PySpark is a live-notebook, viewing-only backend: it must never call `toPandas()`, `toArrow()`, convert through a local dataframe engine, or perform an unbounded `collect()`/iterator. Projection, filtering, sorting, counting, and aggregation stay in Spark. Container profiles use canonical orderable native keys. A page must pass its Spark-side transport-byte preflight before value collection and then remain within its cell, strict-protocol-byte, complex-node, and nesting-depth limits; only that bounded page/value sample or a fixed-size aggregate result may cross into the kernel process.

<!-- OW-RULE:I10 -->
10. File readers expose a shared zero-based Excel sheet index. Failed eager or lazy opens must produce `EngineError` and must not retain a session; nested and scalar values must remain strict-JSON-safe.

<!-- OW-RULE:I16 -->
16. Engine registries contain factories, never shared adapters. Every live or transient session exclusively owns one engine instance; open failures, explicit close, orderly runtime shutdown, and notebook snapshot completion invoke cleanup at most once. The standalone server prepares the selected backend's top-level native module through a separately owned transient adapter on its process-owned stdin reader thread before worker dispatch. For Polars Excel sources only, preparation also initializes discoverable PyArrow there so the native bridge used across the supported `fastexcel` range cannot begin its NumPy-backed import after the reader returns to blocking stdin. PyArrow remains optional, while `fastexcel` and the source read remain worker-dispatched. Do not encode a broader reader-affinity rule without cross-platform evidence. Cleanup faults surface unless an earlier operation already failed. Normal process stops use bounded stdin/EOF shutdown; forced restart may kill only when recovery or the grace bound requires it.

<!-- OW-RULE:I17 -->
17. A live lazy-file session represents exactly the source version fingerprinted while it opened. Every data read validates that fingerprint before and after work; a replacement, resize, schema change, or deletion must invalidate cached blocks and return a recoverable reopen diagnostic without preventing close. Initial open never profiles columns. Page blocks are session-local and bounded by both entry count and payload weight, and every filter, draft, plan, source, or disposal change invalidates them.

<!-- OW-RULE:I21 -->
21. The bundled runtime version lives in `python/openwrangler_runtime/version.py`, drives Python package metadata and the initialize handshake, and must remain PEP 440-equivalent to `package.json`; `npm run docs:check` enforces this.

<!-- OW-RULE:I23 -->
23. Pandas custom code receives recursively isolated object-dtype cells so draft, rollback, and generated-code execution cannot mutate nested source objects. Live and generated filters must distinguish null from NaN exactly as typed cells and saved notebook snapshots do; requesting NaN inclusion for a non-float column is a valid explicit-false value condition, never an empty expression or ignored filter.

<!-- OW-RULE:I25 -->
25. DuckDB file sessions retain only a connection-free native SQL plan plus immutable column and type metadata. A file-session `DuckDBPyRelation` may exist only inside one request-owned hardened connection scope; it must be dereferenced before that connection closes because DuckDB 1.5 relations retain their connection owner. Live DuckDB notebook viewing is the sole exception: one engine-owned wrapper may retain the exact user-owned relation and serialize native `relation.query()` calls on its originating connection. Closing releases only Open Wrangler's reference and never closes or mutates the user's relation. Notebook DuckDB remains viewing-only with cleaning, code insertion, and data export disabled. Never use `DuckDBPyRelation.close()` for cleanup because it executes an unexecuted relation and closes only its result. Extension auto-install, autoload, and external-file caching stay disabled. File terminal reads use independently owned short-lived connections, shutdown interruption is not advertised as request cancellation, and every owned connection is closed deterministically.

<!-- OW-RULE:I53 -->
53. Pinned and auto-detected PySpark notebook opens probe the exact selected kernel generation immediately before authoritative runtime dispatch. Only strict PySpark 4.2.x may proceed; missing, malformed, stale-type, or other-version probes fail with recovery guidance and zero runtime open dispatch. A kernel switch or restart invalidates the lifecycle and reprobes the replacement. The variable picker and opening progress label PySpark viewing-only and its open as bounded and progressive. Opening must not run a full count, `zipWithIndex`, persist/cache the complete relation, or aggregate across every partition merely to validate the first page. Pages use one-row lookahead, retain a bounded boundary history, and fail closed if Spark recomputation changes a checked boundary. Row-byte lengths and Spark-side guarded values share that page's one terminal action. Only a terminal short page promotes the current view to an exact total and invalidates earlier unknown-total cache entries; promotion never unlocks unanchored random offsets. Recovery reconstructs a nonzero viewport through at most 16 contiguous page requests, including when a replacement already reports an exact total, and resets only an over-cap viewport while retaining confirmed filters, sorts, widths, and selection. This supported traversal has a documented ordering limit: an unordered Spark dataframe has no public global order, checked boundaries cannot prove every interior row remained stable, and repeatable sorted rows require a unique final sort key. Queued or superseded work is dropped before dispatch. Work already running in Jupyter is detached and stale-ignored rather than interrupted because PySpark's default SIGINT handler may cancel unrelated Spark jobs.
