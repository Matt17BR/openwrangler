# Open Wrangler agent guide

This repository builds the open-source Open Wrangler extension and its bundled Python runtime. Read this file before changing code. The product is a clean-room implementation: use public documentation and black-box behavior as references, but never copy Microsoft Data Wrangler code or assets.

## Architecture map

- `src/extension/` owns VS Code APIs, runtime lifecycle, sessions, commands, custom editors, and notebook integration.
- `src/shared/` owns the versioned messages and behavior shared by extension and webviews.
- `src/webviews/` owns the React UI. It must remain themeable, keyboard accessible, and independent of Node APIs.
- `python/openwrangler_runtime/` owns dataframe engines, queries, transformations, profiling, code generation, and exports.
- `docs/architecture.md` records boundaries and invariants.
- `docs/feature-parity.md` is the release gate for user-visible parity.
- `docs/reference.md` is generated from public interface registries; never edit it by hand.
- `docs/testing.md` defines required checks and manual editor scenarios.
- `docs/releasing.md` defines packaging and release rules.

## Non-negotiable invariants

1. Pandas, Polars, and DuckDB paths remain engine-native. Polars code must never call `to_pandas()`; DuckDB code must never convert through Pandas, Polars, or Arrow.
2. Viewing filters/sorts are separate from committed cleaning steps and never alter the source.
3. User data is not overwritten. Exports target a separate destination and use atomic replacement.
4. Python execution, dependency installation, custom code, and exports require a trusted workspace.
5. Every runtime request is versioned, validated, correlated, cancellable where possible, and safe to ignore when stale.
6. Disposing a panel closes its runtime session. A runtime crash rejects pending work and offers replay/recovery.
7. Webviews use VS Code theme tokens, a restrictive CSP, same-origin validated messages, accessible labels, and keyboard navigation. User-derived keys belong in `Map`/`Set`, never dynamic object properties.
8. `scratch.txt` and all other untracked user files are user-owned. Never edit, delete, stage, or package them.
9. Do not describe the project as feature-parity complete until every in-scope row in `docs/feature-parity.md` is green.
10. File readers expose a shared zero-based Excel sheet index. Failed eager or lazy opens must produce `EngineError` and must not retain a session; nested and scalar values must remain strict-JSON-safe.
11. Every operation change needs matching runtime and executable generated-code tests for every editing-capable engine. Generated categorical columns may not collide, and engine-specific null/Unicode/aggregate defaults must be normalized explicitly. Integer group sums and by-example arithmetic share the checked `-(10^38 - 1)..10^38 - 1` envelope; nullable wide Pandas values and decimal mean/median normalization require typed-page regressions.
12. Standalone runtime startup is single-flight per Python-selection scope. A workspace folder, exact external resource, and the default resource own distinct process/start/stop, pending, provisional, and confirmed-session state; session requests and cancellations route only through their exact owner. A requested session ID may route only cleanup while provisional, becomes confirmed only through its exact still-pending open response, and any late or ambiguous promotion restarts only that scope. Restart must invalidate the pending start, and closing the final session in a scope must stop its Python process; packaged seed/verify acceptance guards these lifecycle rules.
13. Cleaning-plan shortcuts must be state-scoped, mirrored inside the webview, documented in the generated reference, and tested without intercepting editable-field undo.
14. Saved notebook-output queries use the pure `src/shared/snapshotModel.ts` model through the same coordinator and panel request path as live sessions. Type-specific predicates, exact selections, literal case-insensitive value search, null/NaN treatment, and per-backend sort placement must match live runtime semantics and remain directly unit-tested.
15. Visual baselines and axe acceptance use the lockfile-pinned Playwright Chromium plus deterministic Liberation Sans/Mono harness tokens. Install Chromium with `npx playwright-core install chromium`; do not silently fall back to a moving system browser or distribution font. CI must retain actual/diff artifacts on failure. On POSIX, axe runs keep browser data in their private workspace root and expose only its temp directory through a mode-0700, short-lived `/tmp/ow-a11y-*` symlink so Chrome's singleton socket stays below the Unix path limit; nested cleanup must remove both paths.
16. Engine registries contain factories, never shared adapters. Every live or transient session exclusively owns one engine instance; open failures, explicit close, orderly runtime shutdown, and notebook snapshot completion invoke cleanup at most once. The standalone server prepares the selected backend's top-level native module through a separately owned transient adapter on its process-owned stdin reader thread before worker dispatch. For Polars Excel sources only, preparation also initializes discoverable PyArrow there so the native bridge used across the supported `fastexcel` range cannot begin its NumPy-backed import after the reader returns to blocking stdin. PyArrow remains optional, while `fastexcel` and the source read remain worker-dispatched. Do not encode a broader reader-affinity rule without cross-platform evidence. Cleanup faults surface unless an earlier operation already failed. Normal process stops use bounded stdin/EOF shutdown; forced restart may kill only when recovery or the grace bound requires it.
17. A live lazy-file session represents exactly the source version fingerprinted while it opened. Every data read validates that fingerprint before and after work; a replacement, resize, schema change, or deletion must invalidate cached blocks and return a recoverable reopen diagnostic without preventing close. Initial open never profiles columns. Page blocks are session-local and bounded by both entry count and payload weight, and every filter, draft, plan, source, or disposal change invalidates them.
18. View-query freshness is determined by an opaque logical-view context plus each request's `viewRequestId`, never by filter equality or session revision alone. Mutations and exports remain exclusive; one read-only foreground query may overtake a leased immutable profiling view, profiles use bounded background capacity, and closing cancels queued profiles then waits for active leases. Partial summaries, statistics, values, errors, and pages may update UI or retained panel state only when their request still belongs to the confirmed active view.
19. Cancellation is authoritative only when the original runtime request returns its own correlated response. A cancellation acknowledgement may remove queued work, but it must never synthesize completion for already-running work or hide a mutation that may have committed.
20. Runtime and webview mutations publish atomically. A failed preview/apply/discard/undo restores revisions, plans, drafts, metadata, page/cache state, code, selected column, and progressive-profile ownership to the last confirmed snapshot.
21. The bundled runtime version lives in `python/openwrangler_runtime/version.py`, drives Python package metadata and the initialize handshake, and must remain PEP 440-equivalent to `package.json`; `npm run docs:check` enforces this.
22. `closeSession` is terminal cleanup: its revision is advisory so a caller holding the last confirmed revision can still dispose a runtime that may have committed an ambiguous response. Unknown sessions remain errors, and cleanup still runs at most once.
23. Pandas custom code receives recursively isolated object-dtype cells so draft, rollback, and generated-code execution cannot mutate nested source objects. Live and generated filters must distinguish null from NaN exactly as typed cells and saved notebook snapshots do; requesting NaN inclusion for a non-float column is a valid explicit-false value condition, never an empty expression or ignored filter.
24. Live-kernel opens carry a host-generated `requestedSessionId`. A failed, cancelled, timed-out, malformed, or mis-correlated open must issue a fresh bounded close for that known candidate ID so lost kernel output cannot orphan an unaddressable runtime session.
25. DuckDB file sessions own a hardened connection with extension auto-install and autoload disabled. Lazy relations stay native, terminal reads use independently owned short-lived connections, shutdown interruption is not advertised as request cancellation, and every connection is closed deterministically.
26. Persisted cleaning state is keyed by both source identity and confirmed backend. Recovery replays with that backend pinned; an automatic fallback must never reinterpret a saved plan through another engine.
27. Persisted cleaning and viewing sections recover independently. A missing, malformed, or stale view falls back to an empty view on the cleaned runtime without dropping valid steps or a draft; only cleaning replay failure may reopen the immutable original. Debounced presentation state must flush before a webview can disappear.
28. Applied-step inspection is bounded, read-only, and ephemeral. It may replay only the selected prefix, never mutate revisions or caches, and must clear across panel switches, recreated webviews, recovery, mutation, disposal, Original Data, and Escape while restoring the exact confirmed view. Diff truncation accounts for rows on either side of the returned block.
29. All 26 operations that address input columns accept only public `{id, name}` references: row/order, structural, categorical/text/numeric/datetime, `groupBy` keys and aggregation inputs, and `byExample` source/program leaves. Transform filters/sorts remain a distinct stable-reference IR from name-addressed viewing queries. By-example inputs are ordered arrays aligned to source-reference order; name-keyed maps and legacy strings are invalid. The runtime binds each reference against the exact input schema and lineage to a private `{id, name, position}` before adapter dispatch; persisted steps and protocol metadata never expose positions. Unknown, stale, type/name-mismatched, malformed, or disallowed repeated identities, duplicate input-lineage IDs, output collisions, private row-identity names, and non-portable group/by-example type combinations fail closed. Repeated group aggregation inputs are valid when aliases are unique. Pandas live execution and generated code address bound inputs positionally under duplicate and non-string labels; Polars and DuckDB receive verified native names. By-example synthesis stays within 16 sources, 64 examples, 256 AST nodes, depth 64, 64 concat parts, 8 KiB per string, and 64 KiB total UTF-8 text, with budgets checked before synthesis and after canonicalization. There is no compatibility fallback. Edited latest steps retain their IDs and derive globally unique outputs as `c:step:<stepId>:<created-output-ordinal>` so replay publishes the same lineage.
30. Webview build assets must use bundle-relative URLs and the webview CSP must allow their exact origin. In particular, the packaged Codicon font must resolve beside `webview.css` and `font-src` must allow `webview.cspSource`; an absolute `/codicon.ttf` URL or blocked font is a release-blocking visual defect. Browser baselines must exercise the actual production CSS and font asset.
31. The private row-identity namespace is case-insensitively unreachable from every public operation, including legacy string-based column parameters and aggregation aliases. Pandas must recognize its sentinel under flat and MultiIndex columns; DuckDB must reject schemas whose identifiers differ only by case before they can target the wrong stable column. Binding rejects explicit drop-all and the post-transform guard rejects dynamically empty encoders or custom code; immutable zero-column sources remain valid where an engine supports them. A webview may hold only one draft: every add-operation and edit-latest entry point stays disabled until apply/discard, the no-argument Add Cleaning Step command opens the generic operation picker, and a new draft diff uses the immediately previous committed schema while a replacement uses the recorded latest-step input schema.
32. Every schema crossing the host/webview or runtime boundary has non-empty, unique column IDs and positions exactly `0..n-1`. This applies independently to active, latest-step-input, and applied-step inspection schemas; malformed kernel/runtime responses fail before entering session or UI state.
33. Every live grid page is a required two-dimensional window. Open, page, preview, inspection, apply, discard, and undo requests carry bounded row and column ranges; each response carries the exact ordered stable column IDs aligned with every row value vector. Cache identity includes the resolved projection. Pandas projects by position, lazy Polars projects before collection, and DuckDB uses an explicit terminal select while still fetching the private row ID. Full-schema ARIA coordinates, filters, sorts, generated code, and exports remain independent of the transported projection. Saved notebook snapshots stay full-width because they have no live session for missing blocks; legacy MIME-v2 pages without `columnIds` migrate only after an exact schema-width check.
34. The public dependency-install command accepts no confirmation state and always shows a modal naming the exact requirements and interpreter; only its literal affirmative action may run pip. The `OPEN_WRANGLER_EXTENSION_TESTS=1` activation API exposes only a deterministic decline—there is no modal-free affirmative path or sticky production override. `openWrangler.pythonPath` changes and later successful probes invalidate stale install targets, while a decline preserves the current retryable diagnostic.
35. Live engines, generated cleaning code, and saved notebook snapshots share `fixtures/view-literal-contract.json` for typed viewing values. Literal search and case-insensitive contains use portable ASCII folding while non-ASCII code points remain exact; Pandas semantic-string equality collapses equivalent numeric/boolean/decimal native values without collapsing display-equivalent strings, and ambiguous value labels round-trip only through a bounded versioned `TypedSelectionToken`. The notebook producer enforces its UTF-8 cap incrementally and may never allocate a complete oversized encoding merely to reject it. URI-addressed Jupyter lookup requires the captured `NotebookDocument` to be the sole open object for that URI before and after every await; cleanup still targets the exact dispatched kernel.
36. After trust and active-code prerequisites pass, the public Python-script export command accepts no destination argument and always uses VS Code's Save dialog. Only the environment-gated test API may supply a deterministic destination, and it must call the same source guard and writer. The coordinator pins the immutable open-request source instead of trusting runtime-returned source metadata. Script exports accept only the current local host or matching VS Code remote authority, protect every retained source URI/path through normalized, canonical, and usable filesystem-identity checks, reserve an exclusive sibling temp, flush and close it, revalidate that temp's type/identity plus the source, destination, parent mapping, and remote authority immediately before one atomic rename, and clean only that still-identified temp on failure. Never truncate, unlink, follow, or replace the active source or a destination symlink.
37. On Linux, native VS Code/Cursor acceptance defaults to the zero-window headless Ozone platform with desktop display and editor-IPC variables removed; login-shell environment resolution, updates, telemetry, crash reporting, and persistent secret storage are disabled; and each invocation owns one mode-0700 `tmp/ow/x-*` root for runtime, home, config, cache, data, profiles, a copied fixture workspace, and inherited temporaries. Runtime component names must keep VS Code's Unix socket below the platform path limit, and a nested `finally` must delete the complete per-run root only after editor/display ownership is verified; invariant 40's fail-closed rule takes precedence when it is not. Acceptance must never silently fall back to the current desktop, the shared system temp filesystem, the repository workspace, or normal editor profiles. Cursor requires a functioning session-bus address for GTK initialization even in headless Ozone, so retain that address while removing keyring, SSH-agent, desktop-session, and editor-IPC routes. A visible, potentially focus-stealing run requires the explicit `OPEN_WRANGLER_EDITOR_DISPLAY=current` debug opt-in; `OPEN_WRANGLER_EDITOR_DISPLAY=xvfb` is an explicit compatibility fallback and must remain isolated. Packaged acceptance also owns a separate fresh user-data profile with Workspace Trust enabled and startup prompts suppressed; its `restricted` phase must omit `--disable-workspace-trust`, prove `workspace.isTrusted === false`, and keep the installed Open Wrangler package inactive with no custom-editor tab, coordinator export, session, or runtime.
38. Every live notebook launch owns the exact open `NotebookDocument` captured at command or renderer-message receipt; renderer actions additionally require the exact visible sender `NotebookEditor`. Never recover origin from `activeNotebookEditor` after an await, a URI match, or another split. Retain document identity through coordinator state, Jupyter activation, kernel lookup, bootstrap, dispatch, response publication, recovery, and generated-code insertion. Each dispatched session ID stays mapped to its exact kernel so a malformed, cancelled, timed-out, stale, or mis-correlated open can make one bounded direct cleanup attempt even after lifecycle invalidation. Terminal close may use that mapped kernel but must never reacquire by URI against a replacement document. Generated-code insertion must repeat its exact-object/version/uniqueness preflight immediately before dispatch and report success only after that same document contains the uniquely marked cell. Because the stable VS Code notebook-edit API is URI-addressed, an accepted edit that cannot be proven against the original object is indeterminate and must never be retried, rolled back, or reported as successful; a stale pre-dispatch origin fails without editing a replacement.
39. The primary **Open in Open Wrangler** action on every saved MIME-v2 output creates exactly one coordinator-owned, ephemeral `SnapshotBridge` session even when a canonical `variableName` link exists; that link may expose only a separate, explicit **Open live variable** action bound to the exact originating notebook. The snapshot bridge generates its own public identity, accepts only a canonical full-width capture, strips the live link from published source state, treats captured rows as the complete data truth, recomputes metadata and profiles, and never trusts saved identity, source locations, capabilities, viewing state, cleaning state, or statistics. It never acquires Jupyter, persists state, mutates data, exports data, or claims executable lineage. Producer and consumer caps must stay identical at 10,000 rows, 2,048 columns, 100,000 cells, 16 MiB, 64 graph levels, and 1,000,000 graph nodes plus their field-text limits; capture performs no eager profiling, and lazy Polars collects only one bounded terminal page. Truncation is labeled before expansion, panel disposal closes the session exactly once, and malformed, unknown, ambiguous, type-mismatched, or type-incompatible viewing queries fail closed.
40. Native editor phases keep a 300-second hard deadline and a 180-second changed-checkpoint inactivity deadline. They publish exclusive atomic progress/results under a strict per-phase `protocol`/`runId`/`phase` envelope, pin each result's first-observed file identity through the final read, classify every failure with editor/version/phase/exit context, and never retry automatically. Major extension-host checkpoints use bounded, exclusive, randomized, no-follow sibling temporaries; a publication or identified-temp cleanup error fails the test. Phase stdout/stderr is captured under fixed bounds, discarded on success, and redacted before failure reporting. Editor CLI, workbench, and private-display processes inherit only the explicit platform/isolation allowlist plus runner-owned test values; unrecognized, credential-bearing, and authenticated-proxy variables never reach them. A late `ChildProcess` error may never impersonate exit, and downloader, editor, or display ownership uncertainty must propagate. POSIX launches own a process group. Windows launches own a kill-on-close Job Object through the strict parent-leased supervisor; its random job-empty attestation is absent from the target environment, emitted exactly once only after `ActiveProcessCount == 0`, and required before phase contents or full evidence may open. Attestation ambiguity latches permanently, its correlated control marker is removed before stderr accounting or diagnostics, and a Windows-owned launch with non-piped stderr is rejected before spawn. The runner closes the supervisor's control stdin on every settled path. Native Windows CI must compile the real supervisor and prove natural descendant containment, forced termination, and malformed-frame rejection. If any editor/display ownership cannot be verified, restore the caller environment from captured lexical values only, publish no diagnostic artifact or output path, and do not stat, canonicalize, open, read, traverse, or remove any inherited private runtime/root/profile/result/progress/log path. Package discovery, display setup, installation, phase, and cleanup failures retain diagnostics before verified private-root deletion; cleanup faults use an explicit `cleanup` phase that records the originating phase. Full evidence inputs are source-count, scan-byte, and per-file bounded, use one verified descriptor, and fail closed on non-regular files, hard links, identity changes, containment changes, private-key material, or redaction failure. Only the redacted allowlist documented in `docs/testing.md` may survive in one receipt-bound, re-redacted, sealed JSON artifact outside the prelaunch staging root. A detected pre-close failure must flush a zero-length scrub through the still-owned descriptor before close; a close error reported after that descriptor is already closed may remove only its still identity-matching path. A successful artifact captures its authoritative post-close snapshot in a frozen path/parent/file-identity/size/SHA-256 receipt and is revalidated immediately before `GITHUB_OUTPUT`. CI uses a fresh randomized parent below `RUNNER_TEMP` (mode 0700 on POSIX), uploads only the exact emitted non-glob path in the immediately following step, and retains failure-only artifacts for seven days; local failures print and retain their exact repository-`tmp` path without sweeping prior untracked bundles. Because `actions/upload-artifact` is pathname-only, the GitHub runner and pinned action are trusted after editor/display tree-empty attestation, and arbitrary same-UID post-attestation interference—including the narrow interval after final receipt validation—is explicitly outside the threat model. Raw profiles, settings, storage, databases, arbitrary logs, and secrets must never enter artifacts, and no evidence is created on success or ownership uncertainty.
41. Dependency probes are single-flight only for the exact canonical package-root identity, normalized fully qualified executable, Python version, and ordered dependency descriptors. Scope invalidation, package mutation, and shutdown detach the exact in-flight and completed owners; every joined consumer of a detached probe fails stale, and a late success or rejection cannot delete or publish over a same-key replacement. Successful completed results use an independent 128-entry LRU whose hits refresh recency; LRU eviction may cause only a harmless repeat probe. Probe failures are never cached, missing-requirement order remains stable, and no probe subprocess is cancelled or awaited during bridge shutdown.

42. Import options are exact and format-specific. Excel selectors are mutually exclusive: interactive prompts produce one nonblank `sheetName` or safe non-negative zero-based `sheetIndex`, while a selector-free default means index 0. Delimited options accept no Excel fields, and delimiter/quote values are exactly one Unicode scalar value; lone UTF-16 surrogates are invalid. There are no legacy `sheet` or mixed-format aliases. Automatic selection excludes Polars for a multibyte UTF-8 delimiter and excludes Polars/DuckDB for a multibyte quote; an incompatible pinned backend fails before interpreter resolution, dependency probing, or runtime startup. Changing options for a live file is a host-owned transaction under the same immutable source and public session ID: synchronously flush pending view state, interlock operation UI and runtime/view-state messages, quiesce accepted work, open one host-identified candidate, replay the confirmed plan/draft/view, publish once, and retire the prior runtime without restart-on-timeout. A correlated replacement is authoritative immediately: its source, revision, and snapshot are adopted before asynchronous workspace-state persistence, while a superseding generation suppresses only stale UI publication. The confirmed publication includes regenerated engine-native code plus any draft diff, warnings, and input schema under the new public revision; stale presentation messages are ignored. Every error, cancellation, stale/malformed response, replay failure, or close race leaves the confirmed snapshot intact and cleans the addressable candidate exactly once. Candidate and retired cleanup retain delegate ownership until settlement, and neither option changes nor any first/fallback terminal cleanup may start a missing runtime or write the source. Every correlated file `sessionOpened` may update the bounded `openWrangler.confirmedFileConfigurations.v2` registry. Its strict entries are keyed by canonical file URI and keep the resolved backend separate from the logical `auto` or explicit backend preference; CSV/TSV/Excel require exact import options, while Parquet/JSONL require that field to be absent. There is no compatibility alias. VS Code permits one Open Wrangler custom editor per URI, and recreation must rehydrate and pin that last confirmed source/backend before the unchanged cleaning/view persistence lookup without converting `auto` into an explicit pin for later import reconfiguration.

43. A successful webview `postMessage` is not renderer hydration. Recreated or delayed renderers use finite visibility-aware snapshot pulls until the matching replay marker commits; the host publishes one fresh opaque completion marker only after the retained snapshot/error, presentation, view state, import response, and busy state, and accepts only the exact acknowledgement emitted after React commits that replay. Native import-option actions use a separate opaque correlation ID with one bounded host fallback; manual and correlated intents coalesce, every preparation path first flushes pending view state, and stale, busy, or late renderer responses must never lose or duplicate the transaction.
44. Optional Python-extension environment selection is resource-scoped and event-driven without a hard extension dependency. Activation is single-flight, subscribes to the stable selection event before use, and becomes terminal on disposal. Workspace-folder, exact-file, same-folder sibling, and unscoped events invalidate only current affected scopes; an explicit `openWrangler.pythonPath` ignores those events. Every awaited resolution/probe checks its per-scope epoch. Bare commands resolve only through fully qualified PATH entries and can never be workspace-shadowed; a wrapper is replaced by the absolute `abspath(sys.executable)` it reports, while the executable is never realpathed away from a virtual environment. Windows system discovery uses only the no-install `py -0p` listing and then starts a direct supported `.exe`; dependency probes, pip, and runtimes reject every non-fully-qualified executable. Environment and dependency probes use isolated Python with a controlled environment, return the supported version plus a canonical absolute `realpath(sys.prefix)` and usable string-safe filesystem identity with a 64-bit device and up-to-128-bit inode, and reject an all-zero identity. Live runtimes inherit only owned Python controls and the bundled runtime path, never a host `PYTHONHOME`, `PYTHONPATH`, user site, virtual-environment marker, or launcher override. A confirmed pip mutation invalidates every current selection and process sharing that exact package-root identity, even through executable, symlink, junction, or `/proc` aliases or after its initiating target became stale, while preserving a newer genuinely different package environment. Dependency results are additionally partitioned by normalized executable and exact Python version so distinct interpreters under one shared prefix cannot reuse one another's probe.
45. Standalone Python scope retention is one aggregate bundle keyed by selection scope and is bounded to 128 inactive bundles by a monotonic LRU that never reorders runtime slots. Exact-object leases plus local and global pending, provisional, confirmed-session, cancellation, process/start/stop, stopping-child, and actionable missing-dependency ownership prevent eviction; live or leased scopes may temporarily exceed the cap and must trim immediately when ownership releases. Exact synchronous eviction revalidates the slot identity, removes only its matching selection/epoch/recency state, and scrubs its diagnostics and stale process-selection references. Completed dependency probes are bounded independently by invariant 41 and are never retained or evicted merely because a resource scope exists or disappears. A rejected stop remains owned until that exact child later exits. Stale continuations and lease releases must never mutate a same-key replacement, and an orphan unresolved selection fails closed.
46. Dependency installation owns one exact no-shell, output-ignored `python -I -m pip install --no-input --no-user` child whose executable is the fully qualified interpreter already confirmed by the isolated environment probe. It disables pip configuration files, denies every inherited `PIP_*` control except the explicit index/proxy/certificate/cache/network allowlist, and shares the controlled Python environment used by probes. Every interpreter runs from a private mode-0700 empty working directory that is retained until exact close and removed without recursive deletion. Before spawn, a package-root-identity-keyed mutation barrier invalidates dependency/selection state and must quiesce active, pending-start, and already-stopping runtimes for that probed environment; executable/filesystem aliases are one mutation domain, while different identities remain independent. The approval has its own target-scoped event epoch, and after quiescence the bridge must recheck lifecycle, Workspace Trust, current normalized executable, exact Python version, canonical root identity, requirements, and barrier ownership with no intervening await before spawn. A stopping child is registered before active ownership is cleared or external cancellation-listener cleanup runs. Post-spawn `close` is the only exit proof. Shutdown may wait briefly and unref once, but it must never signal or kill pip. Missing close confirmation latches the same shutdown failure and retains the barrier/scope lease until exact late close; pending modal/progress work and late completion may publish no UI or cache state after disposal. Successful close releases the mutation barrier before a non-action informational notification is published.
47. Native import-prompt acceptance treats workbench visibility and keyboard focus as separate asynchronous states. Before any keyboard navigation, fill, or acceptance, it must use the complete existing 10-second workbench budget to poll for the editor's natural DOM focus transfer without calling `focus`, clicking, or sending input through a locator that would assign focus. A prompt that never receives focus remains a hard failure; retained diagnostics may contain only bounded structural active-element metadata and never input values, labels, or user text. For a final InputBox whose acceptance can immediately replace the active editor, genuine key-down and key-up CDP commands are queued back-to-back before either acknowledgement is awaited; both must settle under the unchanged Node-owned operation deadline.
48. Native notebook-renderer discovery is observation-only. Under the remaining 30-second discovery budget, each exact-preview/role/name probe may inspect only presence, visibility, and enabled state under its own Node-owned deadline; it must not scroll, focus, click, or wait for pointer-style layout stability. Only proven-retired auxiliary pages or detached child frames may be skipped; workbench closure, CDP disconnection, detached workbench main frames, and all live-target failures fail closed. The provenance scenario must reassert the exact other notebook remains active immediately before dispatching the separately recorded DOM action from the origin renderer. Missing, hidden, disabled, disconnected, or nonfunctional actions remain hard failures, and timeout diagnostics are target-count-bounded structural state only—never URLs, labels, rendered text, cell values, or other user-derived content.

## Required checks

Run the narrowest relevant tests while iterating, then run all of these before a milestone PR:

```bash
npm run check
npm test
npm run test:extension-host
npm run test:webview-acceptance
npm run test:coverage
npm run license:check
npm run benchmark:runtime # required for performance/runtime changes and release candidates
npx playwright-core install chromium # before local visual capture/verification
npm run clean
npm run build
npm run capture:screenshots # for visible changes
npm run package -- --pre-release --out openwrangler.vsix
npm run verify:vsix -- openwrangler.vsix
npm run test:packaged-editors -- openwrangler.vsix
```

For editor-facing changes, also complete the relevant scenarios in `docs/testing.md` in both VS Code and Cursor using isolated profiles.

## Documentation update matrix

- Protocol, session, runtime, or engine boundary changes: update `docs/architecture.md` and protocol tests.
- New or changed operation, filter, export, or entry point: update `docs/feature-parity.md` and its acceptance evidence.
- New or changed command, setting, operation, MIME type, or protocol message: run `npm run generate:reference` and commit `docs/reference.md`.
- Test commands, fixtures, or release gates: update `docs/testing.md`.
- Package contents, versioning, CI, publishing, or credentials: update `docs/releasing.md` and `CHANGELOG.md`.
- User-visible setup or behavior: update `README.md` and `CHANGELOG.md`.
- New third-party runtime or bundled asset: update `THIRD_PARTY_NOTICES.md` and verify its license.

CI runs `npm run reference:check` and `npm run docs:check`; do not bypass them or hand-edit `docs/reference.md`.
